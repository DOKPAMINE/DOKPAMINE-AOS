# 개인 기록 동기화 (NFR-04~06)

`initializeDatabase()`는 마이그레이션만 수행하며 인증 전에는 전송하지 않습니다.
화면은 `repository.books/sessions/reviews/quotes.save()` 또는 `softDelete()`로 먼저 로컬에 저장합니다.
저장 이벤트, 앱 활성화, 네트워크 연결 복구가 전송을 예약합니다.

인증 기능은 계정별 DB 준비와 토큰 저장 뒤 `await syncAfterLogin(repository, accessToken)`을 호출합니다.
복원은 책 → 세션 → 감상 → 문장 순서의 단일 DB 트랜잭션이며, 로컬 수정 대기와 tombstone을 덮어쓰지 않습니다.
잘못된 서버 행은 건너뛰고 정상 행을 복원하며, 복원 요청 실패도 로컬 대기 기록의 업로드를 막지 않습니다(401은 재로그인까지 중지).
오프라인 로그인 복원은 다음 연결 이벤트까지 대기합니다.
명시적 로그아웃에서는 토큰을 삭제하기 전에 `stopRecordSync()`를 호출합니다.
앱에서 다시 로그인하면 `syncAfterLogin(repository, accessToken)`이 구독을 다시 연결합니다. 새 엔진은 snapshot을 한 번만 예약하며 요청 토큰은 엔진 수명 동안 고정됩니다. 중지는 진행 중 요청도 취소합니다.

`getSyncState()`와 `subscribeSyncState()`로 상태를 구독할 수 있습니다.
`reauthentication-required`는 재로그인 안내에 사용하고 토큰이나 기기 기록을 삭제하지 않습니다.
전송은 책 → 세션 → 감상 → 문장 순서이며 `BOOK_NOT_SYNCED`는 부모 책을 다시 올린 뒤 한 번 재시도합니다.
409가 반복되거나 다른 요청이 실패하면 해당 기록은 다음 이벤트에서 다시 시도합니다.
400·403 등 행별 4xx는 해당 행만 대기로 남기고 나머지 전송을 계속합니다.
401·오프라인·네트워크·타임아웃·5xx는 업로드 전체를 중단하며, `failedCount`는 이번 실행에서 전송에 실패한 행과 가장 최근 복원에서 건너뛴 행, 확인이 필요한 감상 충돌의 합계입니다.

감상의 서버 버전은 PUT 응답과 스냅샷에서 받아 SQLite에 저장합니다. `REVIEW_VERSION_CONFLICT`가 오면 해당 감상은 자동 전송을 멈춥니다. 감상 목록과 마이의 동기화 상태에서 충돌을 확인할 수 있으며, 최신 서버 감상을 확인한 뒤 공개 범위를 선택해 초안을 다시 저장할 수 있습니다.
복원 요청 자체의 오류는 상태의 `error`로 구분할 수 있습니다.
성공 응답은 전송한 `localVersion`과 일치하는 행에만 적용합니다.

동기화 API 계약은 `DOKPAMINE-BE/docs/API.md`이며, 문장·snapshot 타입과 요청은 `src/api/types.ts`와 `src/api/endpoints.ts`에 정의합니다.
로컬 숫자 시각은 HTTP 경계에서 ISO-8601 UTC 문자열로 변환하고, 로컬 동기화 메타데이터는 전송하지 않습니다.
snapshot은 서버가 돌려준 기록을 병합하며 응답에 없는 기기 기록을 지우지 않습니다.

## 알려진 한계

snapshot에는 삭제되지 않은 기록만 포함되므로, 다른 기기에서 삭제한 기록을 이 기기에서 자동으로 제거할 수 없습니다.
계정별 DB 격리는 `src/auth/README.md`의 Issue #22 정책을 따릅니다. 소유자를 모르는 구버전 DB는 격리 보존하므로 그 파일의 미전송 기록 자동 이전은 지원하지 않습니다.
snapshot 누락 행을 단순 삭제하면 오프라인 수정과 tombstone을 잃을 수 있어 현재 병합 정책을 유지합니다. 다기기 삭제 전파에는 서버 tombstone 또는 변경 커서 계약이 필요하며 별도 BE·AOS Issue에서 다뤄야 합니다.
