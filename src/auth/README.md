# 인증 화면 (Issue #20)

- `AuthProvider`는 SecureStore의 원문 토큰과 계정·만료 메타데이터가 일치하고 `expiresAt`이 미래인 경우에만 탭 접근을 허용한다. 계정 ID 또는 만료 시각이 없는 이전 세션은 재로그인이 필요하다. 부팅 시 서버 검증 요청을 하지 않아 유효한 세션으로 오프라인 기록을 열 수 있다.
- 첫 실행에는 S-01의 안내 3장을 보여 준다. 완료/건너뛰기의 저장이 성공한 뒤 S-02로 전환하며, 앱 재실행·로그아웃 뒤에도 완료 상태를 유지한다. S-03 가입 성공도 즉시 인증된 탭으로 이동한다.
- 만료 타이머, 앱 복귀, 보호 API의 401에서 재로그인을 안내한다. API는 요청 당시 토큰을 전달하므로 이전 세션의 늦은 401은 새 세션을 만료시키지 않는다. 401에서 원문 토큰·개인 기록을 지우지 않는다.
- 이후 S-81 설정 화면은 `useAuth().signOut()`을 호출한다. 이 함수는 토큰과 만료 메타데이터를 삭제하고 Query 캐시를 비운 뒤 로그인으로 전환한다. 이번 변경에는 설정·마이 화면을 추가하지 않는다.
- 이메일·비밀번호·닉네임 검증 스키마는 명세의 소유권 경계에 따라 `src/auth/validation.ts`에 두었다. BE 계약은 변경하지 않는다.

디자인은 Editorial greeting(seed 1457377042)의 평평한 표면과 왼쪽 정렬을 앱의 기존 종이색·Noto Sans KR·공통 Screen/Card/Button에 적용했다. S-01은 “독서 기록을 어떻게 시작하나요?”, S-02는 “기존 계정으로 어떻게 이어 가나요?”, S-03은 “새 계정을 어떻게 만드나요?”에 답한다. 브랜드 토큰과 Android 전용 범위가 우선하므로 데스크톱 그리드·브라우저 검사는 적용하지 않았다. 샘플 계정·가짜 통계는 없고, 연결된 Android 기기가 없어 화면 캡처와 키보드/TalkBack 수동 검증은 후속 확인이 필요하다.

AOS #19 동기화 연결은 `syncLifecycle.ts` 한 곳의 인터페이스로 분리했다. 앱 루트가 `connectAuthSyncLifecycle({ prepareAccount, syncAfterLogin, stopRecordSync })`로 DB 준비와 `src/sync`의 실제 함수를 등록한다. DB 마이그레이션과 기록 저장소 초기화가 끝난 뒤 인증 화면을 열고, 계정 DB 준비·로그인 성공 뒤 복원·전송을 시작하며 로그아웃/만료 시 중지한다. 통합 테스트는 연결 모듈을 그대로 두고 DB·`src/sync` 경계만 목으로 대체해 실제 등록 경로를 검증한다. 동기화 재시도·실패 표시는 엔진이 담당하며, 시작 실패로 인증 성공을 되돌리지 않는다.

SecureStore 읽기 오류 화면에는 재시도와 “다시 로그인하기”를 제공한다. 다시 로그인하기는 동기화를 중지하고 인증 키 두 개만 삭제한 뒤 로그인 폼을 연다. 안내 완료 플래그와 DB의 개인 기록은 지우지 않는다. 키 삭제까지 실패하면 오류 안내와 두 복구 경로를 유지한다.

이번 리뷰에서 유지한 권장 사항은 이전 형식 토큰의 만료 문구, 인증 조회 중 스플래시 종료 시점, 입력 오류의 TalkBack 중복 안내, API 중단 후 내부 Promise 정리다.

## 계정 기록 격리 (Issue #22)

기록 삭제 대신 **계정별 DB 파일 보존**을 선택했다. `user.id`를 세션 메타데이터의 `userId`로 함께 저장하고, `prepareAccount(userId)`로 해당 계정의 마이그레이션이 끝난 뒤에만 탭을 연다. 계정 A의 미전송 기록과 tombstone은 A의 DB에 남으며 B의 저장소·동기화에서는 접근하지 않는다. 다시 A로 로그인하면 기존 대기 기록을 그대로 사용할 수 있다. 이는 API와 테이블 스키마를 바꾸지 않는 클라이언트 저장소 정책이므로 이 범위에서는 별도 공용 ADR 대신 이 문서에 결정을 남긴다.

기존 `dokpamine.db`와 소유 계정 ID가 없는 세션은 소유자를 증명할 수 없다. 기존 파일은 삭제하거나 첫 로그인 계정에 자동 귀속하지 않고 격리 보존하며 재로그인을 요구한다. 서버에 전송된 기록은 계정별 snapshot으로 복원되지만, 구버전 파일의 미전송 기록은 자동 복원되지 않는다. 명시적 소유권 확인과 이전 도구는 후속 작업이다.

앱 시작·로그인 성공에서만 해당 계정 저장소와 토큰을 동기화에 연결한다. 로그인 전에는 DB 초기화만으로 동기화하지 않는다. 마운트 전/저장소 준비 중 수신한 401도 기억하며, 로그아웃 키 삭제에 실패하면 탭과 동기화를 중지한 오류 상태에서 복구하도록 한다. 동기화는 토큰에 고정된 취소 가능한 요청을 쓰므로 이전 엔진이 새 계정의 토큰으로 업로드하지 않는다.
