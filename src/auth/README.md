# 인증 화면 (Issue #20)

- `AuthProvider`는 SecureStore의 원문 토큰과 만료 메타데이터가 일치하고 `expiresAt`이 미래인 경우에만 탭 접근을 허용한다. 만료 시각이 없는 이전 토큰은 재로그인이 필요하다. 부팅 시 서버 검증 요청을 하지 않아 유효한 세션으로 오프라인 기록을 열 수 있다.
- 첫 실행에는 S-01의 안내 3장을 보여 준다. 완료/건너뛰기의 저장이 성공한 뒤 S-02로 전환하며, 앱 재실행·로그아웃 뒤에도 완료 상태를 유지한다. S-03 가입 성공도 즉시 인증된 탭으로 이동한다.
- 만료 타이머, 앱 복귀, 보호 API의 401에서 재로그인을 안내한다. API는 요청 당시 토큰을 전달하므로 이전 세션의 늦은 401은 새 세션을 만료시키지 않는다. 401에서 원문 토큰·개인 기록을 지우지 않는다.
- 이후 S-81 설정 화면은 `useAuth().signOut()`을 호출한다. 이 함수는 토큰과 만료 메타데이터를 삭제하고 Query 캐시를 비운 뒤 로그인으로 전환한다. 이번 변경에는 설정·마이 화면을 추가하지 않는다.
- 이메일·비밀번호·닉네임 검증 스키마는 명세의 소유권 경계에 따라 `src/auth/validation.ts`에 두었다. `src/domain`, DB, 동기화 엔진과 BE 계약은 변경하지 않는다.

디자인은 Editorial greeting(seed 1457377042)의 평평한 표면과 왼쪽 정렬을 앱의 기존 종이색·Noto Sans KR·공통 Screen/Card/Button에 적용했다. S-01은 “독서 기록을 어떻게 시작하나요?”, S-02는 “기존 계정으로 어떻게 이어 가나요?”, S-03은 “새 계정을 어떻게 만드나요?”에 답한다. 브랜드 토큰과 Android 전용 범위가 우선하므로 데스크톱 그리드·브라우저 검사는 적용하지 않았다. 샘플 계정·가짜 통계는 없고, 연결된 Android 기기가 없어 화면 캡처와 키보드/TalkBack 수동 검증은 후속 확인이 필요하다.

AOS #19 동기화 연결은 `syncLifecycle.ts` 한 곳의 인터페이스로 분리했다. 머지 후 앱 조립 지점에서 `connectAuthSyncLifecycle({ syncAfterLogin, stopRecordSync })`로 실제 함수를 등록한다. 현재는 미머지 엔진을 import하지 않는 빈 기본 구현을 사용하며, 로그인 성공 뒤 동기화를 시작하고 로그아웃/만료 시 중지하는 호출은 통합 테스트에서 목으로 검증한다. 동기화 재시도·실패 표시는 엔진이 담당하며, 시작 실패로 인증 성공을 되돌리지 않는다.
